# MAX Account HTTP API — v1.11.2

Python 3.10, Docker, веб-панель на порту **8087**. Изолированные пользовательские аккаунты MAX:
QR-вход, 2FA, все страницы чатов, картинки, Markdown, эмодзи, сохранённые
сообщения, несколько получателей и cron.

Клиент использует неофициальный `maxapi-python==2.4.1` (PyMax).
Это API вашего пользовательского аккаунта, не официальный Bot API.

## Обновление с GitHub одной командой

Выполните **из прежней папки установки**, где лежат `compose.yaml` и `.env`:

```bash
bash -o pipefail -c 'curl -fsSL https://raw.githubusercontent.com/andluk87/max-api/main/scripts/update.sh | bash'
```

Нужны Git, curl, Docker Engine и Compose v2. Команда обновляет `main`, пересобирает
контейнеры и проверяет `/healthz`. Работает и для установки из ZIP: исходники сначала
скачиваются во временную папку, прежние файлы сохраняются в `.update-backups/`.
В ZIP-установке собственный `compose.yaml` остаётся прежним. Если вы меняли Python-код,
сохраните и перенесите свои правки отдельно: обновление заменяет файлы исходников.
Для Git-установки требуется чистое состояние отслеживаемых файлов и fast-forward.

`.env`, данные и Docker volume сохраняются. Используйте прежнюю папку и прежнее
имя Compose-проекта (если задано через `COMPOSE_PROJECT_NAME`), чтобы подключился
тот же volume. Не выполняйте `docker compose down -v`.
Обновите страницу через Ctrl+F5; версия панели — **v1.11.2**.

## Фото и ошибки пересылки в v1.11.2

Исправлена совместимость загрузки фото с URL без `photoIds`. PyMax 2.4.1
отказывался загружать такой файл до HTTP-запроса. Адаптер получает токен из
ответа загрузки: по указанному ID либо по единственному фото в ответе. Пустой,
неоднозначный ответ или несовпадение ID завершаются ошибкой без отправки сообщения.
Адаптер применяется также после переподключения клиента.

При ошибке загрузки журнал содержит безопасный `upload_stage`, без URL и токенов.
Такая доставка отмечается `failed` («Не отправлено»), а не `unknown`. Автоматического
повтора отправок нет; прежние `unknown`-задания не изменяются.

`not.found` на opcode 64 означает отказ MAX: сообщение или чат не найдены либо
недоступны. Проверьте исходное сообщение, чат назначения и доступ подключённого
аккаунта. Это не ошибка соединения; пересылка не заменяется копией и не повторяется.
Реальную загрузку на MAX нужно проверить после обновления с подключённым аккаунтом.

## Вход и завершение сессии в v1.11.1

MAX может временно отвечать `service.unavailable` на вход (opcode 19).
API теперь повторяет вход через 5, 10, 20 и 40 секунд с новым клиентом и прежней
сохранённой сессией. Во время ожидания статус `reconnecting`; после пяти неудачных
попыток — `error`. Это обработка временной недоступности MAX, а не гарантия
доступности внешнего сервера. Ошибки авторизации и отправки сообщений не повторяются.

- `POST /api/auth/stop` — отключить, сохранив сессию. Остановка сохраняется после
  перезапуска API; `POST /api/auth/start` явно возобновляет вход.
- `POST /api/auth/logout` — завершить текущую сессию MAX и удалить её локальную
  базу; история, настройки и другие пользователи сохраняются. В панели это
  кнопка «Завершить сессию MAX».
- При подключении logout вызывает отзыв текущего устройства через MAX. Если
  MAX ответил ошибкой, API возвращает 502/504 и сохраняет сессию для повторной попытки.
  Без подключения удаляется только локальная сессия: ответ `remote_revoked: false`;
  устройство следует завершить в приложении MAX. Новый вход требует QR.

Оба маршрута требуют `Authorization: Bearer <API_KEY>`; администратор может выбрать
пользователя заголовком `X-User-ID`. `logout` возвращает статус, `session_removed`
и `remote_revoked`. Он не завершает другие устройства аккаунта.

## Исправление обычной пересылки в v1.10.3

По журналу v1.10.2 MAX отклонял forward с кодом proto.payload / opcode 64.
В PyMax 2.4.1 link.messageId принудительно сериализуется строкой. Наш адаптер
теперь формирует нативный FORWARD-запрос с целочисленным messageId, source chatId
и отрицательным cid, по форме запроса веб-клиента MAX. Точность 64-битного ID
проверена через настоящий WebSocket-сериализатор PyMax. Режим остаётся обычной
пересылкой, не подменяется копией. Реальная доставка требует проверки на аккаунте.

После обновления проверьте новое оригинальное сообщение с уникальным текстом:
старые unknown-задания и зарезервированные отпечатки не сбрасываются, чтобы
не создать повторных отправок. Если proto.payload сохранится, пришлите свежий
журнал: этот код сам по себе не указывает, какое именно поле отклонил MAX.

## Диагностические логи и wiki

Вкладка «Логи»: уровень INFO/WARNING/ERROR, страницы по 100, экспорт показанного JSON.
HTTP-ошибки показывают X-Request-ID для поиска записи. Журнал хранит до 5000 записей
в diagnostics.sqlite каждого аккаунта и выводит безопасный JSON в stdout контейнера.
Ключи, тела запросов, QR и переписки не записываются. Для ApiError дополнительно сохраняются max_error_code и max_opcode; режим пересылки указан в operation. Класс исключения и места в коде
сохраняются без значений исключения/локальных переменных. Пользователи изолированы;
администратор открывает журнал через панель выбранного аккаунта.
GET /api/logs?level=ERROR&limit=100 возвращает logs и next_before для пагинации.
Успешные GET-опросы не записываются; ошибки до обновления журнал восстановить не может.

Для Docker-лога перенесите секцию logging из нового compose.yaml (3 × 10 МиБ),
сохраняя прежние volumes, имя проекта, порты и свои настройки.

Полная wiki включена в папку wiki: Python-клиент, бот команд, HTTPS, внешний сервис,
справочник API и интерактивная схема Three.js. Wiki запускается вместе с API командой `docker compose up -d --build` из корня проекта.
Откройте http://127.0.0.1:8088; API и панель остаются на 8087.
Для доступа к wiki по IP сервера добавьте `WIKI_BIND_HOST=0.0.0.0` в .env
и пересоздайте сервис: `docker compose up -d --build --force-recreate wiki`.
Это отдельная настройка публичной документации, она не меняет доступ к API.
Для доступа через SSH: `ssh -L 8088:127.0.0.1:8088 user@server`.
Проверка wiki: `docker compose ps wiki`, `docker compose logs --tail=50 wiki`.
Сервис wiki не получает API_KEY и не подключает volume данных аккаунтов.

## Новая установка

Нужны Docker Engine с Compose v2 и Python 3 для создания ключа.

```sh
unzip max-userbot-v1.11.0.zip
cd max-userbot
python3 setup.py
docker compose up -d --build
```

Откройте http://localhost:8087. Введите API_KEY из `.env`, подключите панель,
нажмите «Начать вход» и подтвердите QR на телефоне в MAX. Если потребуется,
введите пароль 2FA. После перезагрузки страницы API_KEY вводится заново.
Существующая сессия MAX восстанавливается при запуске сервера автоматически.

Для доступа по IP сервера укажите `BIND_HOST=0.0.0.0` в `.env` и пересоздайте
контейнер. По умолчанию используется localhost. Для удалённого доступа можно
использовать `ssh -L 8087:127.0.0.1:8087 user@server` или HTTPS reverse proxy.

## Сохранённые сообщения и несколько чатов

1. Во вкладке редактора создайте новое сообщение, затем нажмите «Загрузить все чаты».
2. Отметьте нужные чаты чекбоксами. Фильтрация/поиск не сбрасывают выбор.
   «Выбрать показанные» добавляет только видимые в текущем фильтре чаты.
   Можно добавить числовые ID через запятую. Повторяющиеся ID удаляются.
3. Введите название, текст; при необходимости добавьте картинку.
4. Выберите паузу **5–30 секунд**. Это фиксированная пауза после окончания
   попытки отправки в один чат перед следующей попыткой в рамках этой отправки.
5. «Сохранить» сохраняет сообщение. «Сохранить и отправить сейчас» также
   создаёт задание на отправку всем выбранным получателям.
6. Во вкладке «Сохранённые сообщения» нажмите «Открыть» у нужной строки. После
   редактирования нажмите «Сохранить». «Удалить» удаляет сообщение,
   его расписание и отменяет ещё не начатые отправки этого сообщения.

Можно сохранить сообщение без выбранных чатов, если cron выключен.
Для отправки и включения расписания нужен хотя бы один получатель.
Можно отправлять одну картинку без подписи. Пустой текст без картинки
не сохраняется. Не более 1000 уникальных получателей в одном сообщении.

В очередь попадает **снимок** текста, картинки, списка чатов и интервала.
Последующее редактирование применяется к будущим запускам. Уже созданный
запуск продолжает использовать свой снимок; при необходимости отмените
его и запустите обновлённое сообщение заново.

## Пользователи и администратор

Ключ **API_KEY из .env** теперь является администраторским. Существующие
MAX-сессия, сообщения и расписания остаются у администратора в прежнем volume.
Менять ключ при обновлении не нужно.

Войдите этим ключом и откройте вкладку **«Администратор»**:

- создайте пользователя по имени — его новый ключ показывается один раз;
- передайте пользователю этот ключ для входа в ту же веб-панель/API;
- пользователь подключит собственный MAX через QR; его данные изолированы;
- доступны переименование, замена ключа, блокировка, разблокировка и удаление;
- «Открыть панель» переключает администратора в аккаунт выбранного пользователя:
  подключение MAX, отправки, сообщения, фото, избранное, расписания, история,
  автоматические пересылки — все существующие операции доступны там;
- чтобы вернуться, откройте вкладку администратора и нажмите «Открыть панель»
  у строки «Администратор». Текущий аккаунт всегда подписан над меню.

Пользовательские ключи хранятся **отдельно от .env**: `/data/users.sqlite`.
В базе записаны SHA-256-хеши случайных ключей, а не их открытые значения.
Повторно показать старый ключ нельзя — можно только выдать новый. Замена
немедленно отзывает старый ключ. Сам администратор и его ключ управляются через
.env; удалить или заблокировать администратора из панели нельзя.

Данные каждого пользователя находятся в `/data/users/<внутренний номер>/`:
отдельные сессия MAX, события, сообщения, фото, очереди и пересылки.
Пользователь не может обращаться к чужим данным даже с подставленным заголовком
или известным номером сообщения. Все аккаунты используют порт 8087.

Блокировка отзывает доступ и останавливает подключение и фоновые задачи.
При разблокировке сохранённые задачи могут продолжить работу. Прерванные
отправки с неизвестным результатом автоматически не повторяются. Администратор
может открыть заблокированный аккаунт для просмотра и ручного управления,
но планировщики в нём остаются остановленными до разблокировки.
Удаление отзывает ключ и останавливает задачи; каталог данных перемещается
в `/data/deleted/`. Эти файлы не доступны удалённому пользователю и остаются
для ручного восстановления владельцем сервера. Панели восстановления пока нет.

Статистика администратора включает каждого пользователя и общую сводку:
состояние MAX, время последнего обращения, количество сохранённых событий,
сообщений, избранных чатов, включённых расписаний и правил пересылки;
статусы доставок, прямые отправки API, неизвестные результаты, запросы и
ошибки API, размер файлов и время работы процесса. Есть статистика запросов
по дням (UTC) и журнал последних 100 административных действий.
Это статистика сервиса, а не всей истории аккаунта MAX: история, которую лишь
просмотрели через MAX, не увеличивает счётчик сохранённых событий. Счётчики
прямых отправок и API-запросов накапливаются с установки v1.8.0. Подтверждение
отправки не означает прочтение получателем. Объём удалённых архивов в сводку
активных пользователей не включён.

Пользовательским ключом доступны прежние `/api/*`, кроме `/api/admin/*`.
Администратор может добавить `X-User-ID: <номер пользователя>` для управления
другим аккаунтом. Пользовательским ключам этот заголовок запрещён. Ключи не
передаются через URL и не записываются в журнал действий.

| Метод | Путь | Действие |
|---|---|---|
| GET | `/api/whoami` | Роль и текущий аккаунт |
| GET | `/api/admin/users` | Пользователи, статистика, сводка и журнал |
| POST | `/api/admin/users` | JSON `name`; создать пользователя и получить ключ |
| PATCH | `/api/admin/users/{id}` | JSON `name`; переименовать |
| POST | `/api/admin/users/{id}/key` | Отозвать ключ и получить новый |
| PATCH | `/api/admin/users/{id}/enabled` | JSON `enabled`; блокировка/разблокировка |
| DELETE | `/api/admin/users/{id}` | Удалить доступ, переместить данные в deleted |

Используйте один процесс/worker на volume, как в Dockerfile. Не запускайте
несколько экземпляров с одной базой пользователей.

## Темы оформления Bootstrap

Панель использует локальный Bootstrap 5.3.8; CDN не требуется.
Над вкладками доступны темы «Ирис», «Океан», «Лес», «Роза» и режимы
«День», «Ночь», «Авто». Авто следует настройке системы, включая её изменение.
Выбор сохраняется в localStorage браузера для этого адреса сервера и применяется
также к экрану входа. API-ключи в localStorage не записываются.
Если хранилище браузера недоступно, тема работает до закрытия страницы.
Вид адаптирован к узким экранам; настройки не меняют данные и задания.

## Адреса вкладок

Вкладки имеют прямые ссылки: /#connect, /#editor, /#saved, /#favorites,
/#queue, /#events, /#relays, /#logs, /#admin. Работают кнопки браузера
«Назад/Вперёд». После обновления страницы введите ключ: откроется вкладка
из адреса. Ключ и выбранный пользователь не записываются в URL.
Неизвестная вкладка или #admin для обычного пользователя открывает #connect.
Ссылка на редактор не сохраняет несохранённый черновик при перезагрузке.

## Вход в панель и входящие

До проверки API_KEY отображается только карточка доступа по центру экрана.
Неверный ключ оставляет панель закрытой и показывает ошибку. Enter подключает
панель. После обновления страницы ключ потребуется снова.

Во вкладке «Входящие» слева выберите любой доступный чат MAX: личную
переписку, группу или канал. При подключённом MAX загружаются все страницы
списка чатов, в том числе чаты без сохранённых сервисом событий.
История выбранного чата запрашивается непосредственно у MAX и включает
входящие и исходящие сообщения, в том числе до установки сервиса.
Новые сообщения показаны выше; «Загрузить предыдущие» открывает более старые.
«Обновить» повторно загружает чаты и последние сообщения выбранного чата.
Если MAX отключён, доступен только прежний журнал полученных сервисом событий;
это явно указано рядом со списком. Недоступную аккаунту историю загрузить нельзя.

Карточки отображают форматирование, переданное MAX: жирный, курсив,
подчёркивание, зачёркивание, моноширинный текст, код, заголовки, цитаты,
ссылки и скрытый текст. Переносы и эмодзи сохраняются; смещения форматирования
учитывают UTF-16. Неизвестные типы оформления отображаются обычным текстом.
Фото загружаются браузером по ссылке вложения MAX без передачи API_KEY.
Нажмите «Открыть фото» для просмотра оригинала. При недоступной ссылке
показывается встроенное превью, если MAX его предоставил, либо объяснение ошибки.
Для получения свежих ссылок обновите историю. Видео, опросы и другие типы
вложений пока не воспроизводятся. Интерфейс не является точной копией клиента MAX.

«Импортировать в сообщение» переносит текст, эмодзи и первую фотографию
в новый черновик редактора. Оригинал фото скачивается сервером через авторизованный
API; при ошибке редактор не заменяется. Для импорта фото нужен подключённый MAX.
Если фото несколько, редактор показывает предупреждение: он поддерживает одну
картинку. Пересылки ниже копируют все фотографии (до 10).
При наличии содержимого редактора запрашивается подтверждение замены.
Получатели не выбираются автоматически, расписание выключено. Импорт сам
ничего не сохраняет и не отправляет. В обычный редактор стили текста MAX пока
не переносятся; при пересылке исходные стили сохраняются без преобразования в Markdown.

## Автоматические пересылки новых сообщений

1. Откройте «Пересылки» и нажмите «Загрузить чаты».
2. Задайте название и выберите получателя. Доступны поиск по названию и фильтры «Группы», «Каналы», «Личные». Выбранный получатель остаётся выбранным при фильтрации.
3. Отметьте один или несколько исходных чатов. Список имеет поиск и префиксы
   **[Группа]**, **[Личное]**, **[Канал]**. Под списком видны количество и названия выбранных источников.
4. Выберите паузу 5–30 секунд. Отметьте «Включить автоматическую пересылку
   после сохранения» либо сохраните выключенное правило и включите его в списке.

Выбирать отдельные сообщения, вставлять ссылки и запускать наборы больше не нужно.
Все новые сообщения выбранных источников, полученные сервисом после включения,
автоматически ставятся в очередь. Учитываются и сообщения вашего аккаунта,
если MAX присылает их сервису. Старые события и история до включения не отправляются.
Правило работает на сервере при закрытом браузере. Для получения новых сообщений
нужно соединение с MAX. История за время простоя отдельно не перечитывается:
сообщения, которые MAX не доставил сервису, автоматически восстановить нельзя.

Доступны два режима:

- **Переслать** — штатная пересылка MAX исходного сообщения через `forward_message`.
  Содержимое не пересоздаётся; сохраняются возможности и ограничения пересылки самого MAX.
- **Создать новое** — новое сообщение от вашего аккаунта с исходным текстом,
  нативными элементами оформления, эмодзи и фотографиями. Гиперссылку в конце
  можно отключить. Подпись ссылки — название исходного чата. Можно выбрать ссылку
  на группу/чат либо на конкретное исходное сообщение.

Используются ссылки `https://max.ru/…`, без `web.max.ru`. Для публичных чатов
используется адрес из метаданных MAX, для закрытых — маршрут `/c/…`.
Открытие установленного приложения зависит от устройства и настроек браузера;
закрытые источники доступны участникам. Открытие ссылок закрытых чатов на реальном
устройстве в этой среде не проверялось.

Для копии: текст с подписью до 4000 символов, до 10 фото JPEG/PNG/WebP,
каждое до 10 МиБ и 20 мегапикселей. Неподдерживаемые вложения, например видео,
дают явную ошибку в журнале; содержимое не отправляется частично. Для них
используйте «Переслать».

В обоих режимах пропускаются сообщения, помеченные MAX как `FORWARD`.
Обычные ответы (`REPLY`) не считаются перепостами. Дополнительно сравниваются
точный текст и байты фотографий: одинаковое содержимое в одно назначение
повторно не отправляется, включая разные правила этого аккаунта. Для других
вложений в штатной пересылке сравниваются доступные идентификаторы медиа;
без идентификаторов защита ограничена повтором того же исходного сообщения.
Это не смысловой поиск: изменённый текст или перекодированное фото могут
считаться новым сообщением. Если одинаковые копии не имеют признака перепоста,
отправляется первая полученная, определить первоначального автора по ним нельзя.
Отпечатки хранятся после перезапуска и резервируются перед отправкой:
при неизвестном результате повтор подавляется, чтобы избежать дубля.

В списке можно включить, выключить, изменить или удалить правило. Выключение
отменяет ожидающие сообщения. При следующем включении пересылаются только
последующие новые сообщения. Смена источников или назначения тоже отменяет
старую очередь и начинает отслеживание с момента сохранения. Уже начатая
отправка может завершиться даже после выключения/удаления.

Настройки, курсоры событий, очередь и результаты сохраняются в volume.
Ожидающие отправки продолжаются после перезапуска. Отправка с неизвестным
результатом автоматически не повторяется: проверьте чат назначения вручную.
Повторное получение одного события в рамках правила не создаёт вторую копию.
Интервал применяется между попытками отправки одного правила; журнал показывает
последние 100 заданий только после нажатия «Загрузить последние 100». Фоновое обновление не загружает журнал. Циклы между включёнными правилами и отправка чата в самого
себя запрещены. Задания в очереди сохраняют режим и настройки ссылки на момент получения сообщения. Изменения этих настроек применяются к новым событиям.

При обновлении старые ручные наборы преобразуются в **выключенные** правила
по их исходным чатам. Проверьте назначения и включите нужные правила самостоятельно.
Оригинальные записи старых наборов остаются в базе; автоматическая отправка
после обновления не включается без вашего действия.

## Вкладки и избранное

Верхнее меню разделяет подключение, редактор, сохранённые сообщения,
избранное, очередь и входящие события. Звёздочка рядом с чатом добавляет его
в избранное, но не выбирает получателем. Избранное хранится на сервере.
В редакторе можно показать только избранные чаты или добавить все избранные
к получателям. Во вкладке избранного можно создать новое сообщение с этими чатами.
Удаление из избранного не меняет получателей сохранённых сообщений.

Вкладка сохранённых сообщений содержит общий список с поиском, расписанием,
ближайшим запуском в выбранном часовом поясе и количеством получателей.
Кнопки позволяют открыть, отправить, включить/выключить расписание или удалить
сообщение. У выключенного расписания вместо времени запуска отображается «—».

## Расписание мышкой

Выберите периодичность и время из списков:

- ежедневно — часы и минуты;
- по дням недели — отметьте дни и время;
- ежемесячно — число или последний день месяца и время;
- каждые несколько часов — интервал и минута часа;
- каждые несколько минут — интервал из списка.

Выберите часовой пояс, включите расписание и сохраните сообщение.
Добавлен **Анадырь — Asia/Anadyr (UTC+12)**; по умолчанию для новых сообщений — **Asia/Anadyr**. Сохранённые расписания не изменяются.
Предпросмотр показывает пять ближайших запусков. Ручной ввод cron в панели
не нужен. HTTP API по-прежнему принимает пятичастное поле `cron`.
Сложные расписания предыдущей версии сохраняются при изменении текста;
для замены выберите новый режим в списке.

Расписание работает на сервере, браузер можно закрыть. Выключите его кнопкой
в общем списке либо снимите флажок в редакторе и сохраните. Это не отменяет
уже созданное задание: отмените его отдельно во вкладке очереди.
Числа 29–31 пропускают месяцы без такого дня; «Последний день» подходит
для каждого месяца. Интервалы cron привязаны к границам часа/суток,
а не к моменту сохранения. Переходы летнего времени обрабатывает croniter.

**Простой и совпадающие запуски:**

- Если MAX не подключён в момент cron, этот запуск пропускается.
- Просроченный более чем на 60 секунд запуск пропускается. Пропуски не
  воспроизводятся пачкой после запуска контейнера.
- При опоздании до 60 секунд возможен один запуск, затем рассчитывается
  следующая будущая дата.
- Если у сообщения уже есть активный запуск, новое cron-срабатывание
  пропускается; параллельных отправок одного сообщения не создаётся.
- Ручной запуск без соединения остаётся в очереди до подключения MAX.

## Очередь, ошибки, перезапуск

В разделе очереди показаны последние 30 запусков и результат по каждому
чату. Можно отменить оставшиеся отправки. Запрос, уже переданный MAX,
отменить гарантированно нельзя: он может завершиться после нажатия отмены.

Очередь работает последовательно, один получатель за раз. После рестарта
уже подтверждённые отправки не повторяются. Попытка, прерванная рестартом,
или сетевой сбой получает статус **«Результат неизвестен»** и автоматически
не повторяется. Остальные получатели продолжают обрабатываться. Проверяйте
такие случаи в MAX, прежде чем повторять вручную.

Это не гарантия exactly-once: MAX не предоставляет этому сервису
идемпотентность. Новый ручной запуск завершённого сообщения отправит его
повторно. Удаление сохранённого сообщения не удаляет журнал его запусков.
История запусков и входящих событий пока не очищается автоматически;
контролируйте размер volume. Копия картинки в задании очищается после
завершения/отмены; картинка сохранённого сообщения остаётся до его удаления.

Не запускайте несколько workers/контейнеров на одной базе. Dockerfile
использует один worker. Ключ API даёт управление аккаунтом через этот API.

## HTTP API

Все `/api/*` требуют `Authorization: Bearer <API_KEY>`. Схема доступна по
`/openapi.json`. `/healthz` проверяет HTTP процесс; `/api/status` — MAX.
ID MAX в ответах представлены строками для сохранения точности в JavaScript.

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/status` | Состояние MAX |
| POST | `/api/auth/start` | Начать вход / восстановить сессию |
| GET | `/api/auth/qr` | QR PNG |
| POST | `/api/auth/password` | JSON `password` |
| POST | `/api/auth/stop` | Отключить клиент, сохранив сессию и запретив автозапуск |
| POST | `/api/auth/logout` | Завершить текущую сессию MAX |
| GET | `/api/chats?marker=...` | Страница чатов и `next_marker`; читать до `complete=true` |
| POST | `/api/messages` | Немедленная отправка одному чату: JSON `chat_id`, `text`, `reply_to?`, `notify?` |
| POST | `/api/messages/photo` | Немедленная отправка одному чату: multipart `chat_id`, `photo`, `text?`, `reply_to?`, `notify?` |
| POST | `/api/source/resolve` | JSON `chat_id` и `url` либо внутренний `message_id`; вернуть сообщение и ссылку |
| GET | `/api/source/{chat_id}/{message_id}/photo/{index}` | Скачать проверенный оригинал фото, индекс с 0 |
| GET | `/api/relays` | Правила; журнал по запросу `?include_jobs=true&limit=100` (лимит 1–500) |

| PUT | `/api/relays/{id}` | Обновить правило |

| PATCH | `/api/relays/{id}/enabled` | Включить/выключить правило: JSON `enabled` |

| GET | `/api/inbox/{chat_id}?before=0&limit=50` | Сообщения чата от новых к старым; `next_before` для следующей страницы |
| GET | `/api/updates?after=0&limit=100` | Входящие события, следующий курсор в `next_offset` |
| GET | `/api/favorite-chats` | Список избранных чатов |
| PUT | `/api/favorite-chats/{chat_id}` | Добавить/обновить: JSON `title`, `type` |
| DELETE | `/api/favorite-chats/{chat_id}` | Убрать из избранного |
| PATCH | `/api/saved-messages/{id}/schedule` | Включить/выключить: JSON `enabled` |
| GET | `/api/saved-messages` | Список сохранённых сообщений |
| POST | `/api/saved-messages` | Создать: multipart `payload` (JSON) и необязательный `photo` |
| GET | `/api/saved-messages/{id}` | Открыть сообщение |
| PUT | `/api/saved-messages/{id}` | Полностью обновить настройки: multipart `payload`, `photo?` |

| POST | `/api/saved-messages/{id}/send` | Поставить ручной запуск в очередь; HTTP 202 |
| GET | `/api/send-runs?limit=30` | Состояние очереди и доставки по чатам |
| POST | `/api/send-runs/{id}/cancel` | Отменить оставшиеся доставки |

Старые `/api/messages` и `/api/messages/photo` продолжают работать напрямую
с одним чатом; интервал и cron применяются к сохранённым сообщениям и очереди.

### Создать сообщение с расписанием

```sh
curl --fail-with-body http://localhost:8087/api/saved-messages \
  -H "Authorization: Bearer $API_KEY" \
  --form-string 'payload={"title":"Новости","text":"**Доброе утро!** 👋","chat_ids":["-123456789","987654321"],"interval_seconds":10,"cron":"0 9 * * 1-5","timezone":"Europe/Moscow","enabled":true}'
```

Ответ содержит `id`. Для ручного запуска:

```sh
curl -X POST "http://localhost:8087/api/saved-messages/ID/send" \
  -H "Authorization: Bearer $API_KEY"
```

Для картинки добавьте в JSON `"photo_action":"replace"`, а к curl
`-F 'photo=@image.jpg'`. При редактировании `photo_action=keep` (по умолчанию)
сохраняет прежнюю картинку, `replace` заменяет её, `remove` удаляет.
PUT заменяет все настройки: передавайте нужные title/text/chat_ids/cron
и остальные поля, иначе применяются значения по умолчанию.

Прямое сообщение с фото:

```sh
curl --fail-with-body http://localhost:8087/api/messages/photo \
  -H "Authorization: Bearer $API_KEY" \
  -F 'chat_id=-123456789' \
  -F 'photo=@image.jpg' \
  --form-string 'text=👋 **Привет!** _Картинка для тебя_ ❤️'
```

## Картинки и оформление

JPEG, PNG или WebP до **10 МиБ / 20 мегапикселей**. Фото хранится в SQLite
в volume, а не в браузере. Для reverse proxy нужен достаточный размер
тела (например, `client_max_body_size 12m;` для nginx). Анимация не гарантируется.

| Оформление | Синтаксис |
|---|---|
| Жирный | `**текст**` |
| Курсив | `_текст_` |
| Подчёркивание | `__текст__` |
| Зачёркивание | `~~текст~~` |
| Код | Одинарные обратные кавычки |
| Ссылка | `[название](https://example.com)` |
| Цитата | `> текст` в начале строки |
| Заголовок | `# текст` в начале строки |

Эмодзи — обычный Unicode, включая составные 👩‍💻. HTML не преобразуется.
Это ограниченный Markdown PyMax: inline-стили не переходят через перенос
строки, экранирование обратным слешем не поддерживается. Лимит текста —
4000 символов. Кнопка «Ссылка» вставляет пример URL: замените его своим.

Входящие сообщения сохраняются отдельно и доступны через `/api/updates`.
Пример `examples/ping_bot.py` отвечает на `/ping` в выбранном `BOT_CHAT_ID`.
Это не полный архив истории MAX. Бинарные поля ответа кодируются объектом
`{"encoding":"base64","data":"..."}`.
